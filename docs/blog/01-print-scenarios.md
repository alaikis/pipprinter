# 从文件到纸张：常见打印场景怎么落地

做业务系统时，"把内容打印出来"看起来是件小事，真正做起来却花样很多：有时是一张小票，有时是一摞报表，有时要把数据填进已经印好的单据里。下面按场景梳理荔枝打印助手的处理方式，每一种都给出可直接照做的路径。

## 先理解一件事：我们按"文件"工作，不按"绘制指令"工作

很多打印方案让你在代码里一行行描述"在这里画一段文字、在那里画一个表格"。荔枝打印助手走的是另一条路：你把要打印的内容做成一个**文件**（PDF、Office 文档、图片、网页、纯文本都行），把它交给客户端，客户端负责把文件准确地送到打印机。

这样做的好处是，排版交给最擅长排版的工具，打印这件事只专注打印。你在业务系统里生成的订单、标签、报表，本身是什么样，打出来基本就是什么样。

## 场景一：把一段文字或一张图片直接打出来

最轻量的场景，没有现成文件，只有一段内容。

把文字或图片作为内联内容提交，客户端会按内容特征识别类型并打印。文字按纯文本处理，图片按图片处理。也可以给内容附上带扩展名的文件名，让类型判断更明确。

要点：

- 纯文本内容按文本排版，字体、行距跟随系统默认。
- 图片会按比例适配纸张；需要更精确控制时，先把图片排成 PDF 再打印。
- 边距、份数、方向这些参数对直接排版的内容生效。

## 场景二：打印表格与报表

报表通常是 Excel 或网页表格。这类场景的关键是"别让它变形"。

推荐做法：在业务系统里把报表导出成 PDF 再提交打印。PDF 的页面尺寸和版式是固定的，打印时不会因环境差异跑版。如果报表本来就是 Excel 文件，也可以直接把文件交给客户端。

要点：

- PDF 的页面尺寸由文件自身决定，纸张参数不会强行改变它。
- 缩放方式可选"适合纸张""实际大小"等，用来处理大幅面内容。
- 多页报表可以用页码范围只打其中一部分，例如只打第一页或某个区间。

## 场景三：打印条码与二维码标签

标签打印最常见的问题是"码打出来扫不出来"。这通常由两个原因造成：分辨率不够，或者尺寸太小。

推荐做法：把标签（含条码或二维码）先生成成一张图片或 PDF，再交给客户端打印。这样码的清晰度由生成环节保证，客户端只负责不失真地输出。

要点：

- 二维码要保证足够的物理尺寸，太小的码在普通打印机上容易糊。
- 一维码的条空对比要清晰，避免浅灰等低对比颜色。
- 标签纸的尺寸要在打印机驱动里设置好，客户端的纸张参数会下发给驱动，但最终能否生效取决于驱动和打印机是否支持。

需要说明：客户端有专门的条码打印命令，用于按内容直接生成条码；如果你用的是常规一维码、二维码，用"生成图片再打印"的方式更可控。专门的命令需要显式指定，自动识别不会把一段普通文字猜成条码指令。

## 场景四：套打——把数据填进现成单据

套打指的是纸上已经印好了表格、印章、底纹，你只需要把可变数据打到指定位置。

推荐做法：用 HTML 模板配合数据。把底图作为背景，把可变字段放在精确定位的位置，然后让客户端把模板渲染后打印。模板里的变量用占位符表示，打印时用实际数据替换。

要点：

- 背景、水印、电子印章属于内容，不属于打印参数——请把它们放进文件本身或 HTML 模板里。
- HTML 转成 PDF 时，用 CSS 让背景图形一起输出，否则底纹可能不显示。
- 位置偏移通常来自纸张尺寸或页边距设置不一致，先把纸张两边对齐再微调位置。

## 场景五：批量打印

批量打印有两种做法，按你的实时性要求选择。

**顺序打印**：把多个任务依次加入队列。客户端按顺序处理，适合任务不多、希望立刻看到结果的场景。

**模板加数据**：准备一份模板和一份数据，让客户端按数据批量出单。适合同一张单据要打很多份、每份数据不同的场景，例如批量出库单、批量标签。

要点：

- 队列可以看到每个任务的状态，失败的任务可以单独重试。
- 有新任务入队时，如果主窗口是隐藏的，客户端会自动弹出打印队列页，让你看到进度。
- 批量任务建议先小批量试打，确认版式正确再全量提交。

## 场景六：网络文件与远程打印

文件不一定在本机，也可能在服务器上。

把网络地址放进统一的目标字段即可，客户端会下载并识别类型。识别顺序是：文件名后缀、文件内容的字节特征、响应的内容类型；三者都识别不出会直接报错，不会猜一个格式硬打。

要点：

- 网络链接如果需要鉴权，请在业务系统侧生成客户端可直接下载的地址再提交；下载用标准的 GET，不转发自定义请求头。
- 局域网内的共享文件也可以用统一目标字段传入，客户端会按本机文件处理。
- 远程打印如果涉及跨网络，走的是另一套主动连接机制，需要在设置里显式开启并配置。

## 场景七：不需要人盯着——静默打印

大多数场景希望提交即打印，不弹窗口、不确认。

客户端内嵌的本机服务随程序自动运行，业务系统通过接口提交打印任务，客户端在后台完成打印。这就是静默打印。

要点：

- 静默打印的前提是打印机已经设置好、驱动已经安装、纸张和份数等参数走默认值或随任务传入。
- 没有显式传的参数，会回退到设置页里配置的默认打印参数，避免每次调用都写一遍。
- 打印机驱动由管理员通过打印机厂商的官方渠道安装，客户端只做只读的状态自检，不自动下载或安装驱动。

## 场景八：先看一眼再打——打印预览

有些场景需要先确认效果。

推荐做法：把文件用系统关联的程序打开预览，确认无误后再交给客户端打印。客户端本身专注于"把文件送进打印机"，预览环节交给用户熟悉的文档查看方式更自然。

## 一张表：场景到能力的对应关系

| 场景 | 推荐输入 | 关键设置 |
| --- | --- | --- |
| 文字 / 图片 | 内联内容 | 边距、方向、份数 |
| 表格报表 | PDF 或 Excel | 缩放、页码范围 |
| 条码标签 | 图片或 PDF | 纸张尺寸、分辨率 |
| 套打单据 | HTML 模板 + 数据 | 背景输出、位置偏移 |
| 批量出单 | 队列或模板加数据 | 队列状态、默认参数 |
| 网络文件 | 下载 URL 或共享路径 | 类型识别、鉴权处理 |
| 静默打印 | 接口提交任务 | 默认打印参数 |
