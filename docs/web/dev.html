构建与运行

git clone https://codeup.aliyun.com/alaikis/software/com.alaikis.tools.printer.git
cd com.alaikis.tools.printer

dotnet restore
dotnet build -c Release          # 期望 0 warning / 0 error
dotnet run                       # 启动后驻留系统托盘，主窗口保持隐藏
dotnet run -- --show             # 首次运行/验收时直接显示主窗口（默认「打印队列」页）

# 发布单文件（可选，本地正式包）
dotnet publish -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:Version=2.0.0 -p:AssemblyVersion=2.0.0.0 -p:EnableWindowsTargeting=true \
  -o ./release/publish
启动后请访问 http://127.0.0.1:19861/api/status 确认 Web 服务就绪；若端口被占用，改 config/appsettings.json 的 webPort 后重启。

Gitee 发布流水线（.workflow/pipeline.yml）

Gitee Go 在 master 推送 v* tag 时自动触发，构建 win-x64 自包含单文件包并创建 Gitee Release，同时上传 latest.json 供客户端自动更新。

  1. 本地：实现完毕 → git commit -m "feat: ..." → git tag -a vX.Y.Z -m "PipPrinter vX.Y.Z" → git push gitee master && git push gitee vX.Y.Z
  2. Gitee Go 监听 push.tags.prefix=v，触发 .workflow/pipeline.yml
  3. Stage 1 build@dotnet：dotnet 10.0，dotnet publish -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableWindowsTargeting=true，zip 成 PipPrinter-win-x64-v${VERSION}.zip，并生成 latest.json（含 sha256 + size + url）
  4. Stage 2 release@gitee：创建 Gitee Release vX.Y.Z，上传 zip + latest.json
  5. 客户端：拉取 https://gitee.com/alaikiscom/pipprinter/releases/latest/download/latest.json，对比 version 与本地，sha256 校验通过后下载并替换当前目录
首次发布： 仓库需在 Gitee 控制台开通 Gitee Go 流水线，并在仓库「环境变量」配置 GITEE_API_TOKEN（或允许 release@gitee 步骤使用内置发布令牌）。流水线保存后会往 .workflow/ 目录提交 yaml。

本机指纹（跨浏览器 / 会话稳定）

命令 GetMachineFingerprint（WS / POST /api/command）与 REST GET /api/machine 返回 24 位前缀指纹，由 HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid + C 盘卷序列号 + OS 版本 + 当前用户名做 SHA1 生成，并写入 config/appsettings.json 的 machineId 字段。用途：识别「这台机器」并作为打印习惯 / 打印机偏好的 machine-key；跨浏览器、跨账号会话下指纹不变。

curl http://127.0.0.1:19861/api/machine
# { "code":200, "data":{ "machineId":"PP-a1b2c3...", "machineGuid":"...", "volumeSerial":"...", "os":"...", "user":"..." } }

/impetus 开发规范

阶段流转固定为 open → design → build → verify → archive；方案类变更为 open → design → review → published。每个活跃 change 在 .impetus.yaml 里记录 phase、build_mode、isolation、build_pause。

产物位置要求
提案 proposal.mdopenspec/changes/<name>/含 Why / What / Impact / Non-goals / Risks；正文 ≤ 500 字
设计 design.md同上含 Decisions / Alternatives / Consequences / Verification；UI 决策给可截图验收标准
任务 tasks.md同上复选框 - [ ]，单任务 ≤ 2 小时且可独立验证
增量 spec…/specs/<name>/spec.md## ADDED / MODIFIED / REMOVED Requirements 三段式，每条 Requirement 带 ### Scenario:
状态 .impetus.yamlchange 根目录由 guard 维护，断点恢复时重跑 Step 0/Step 1 判定阶段

提交约定：git commit -m "feat(<change>): 中文描述"；issue_id 为 null 时不自动提交。

新增一个命令（推荐做法）

  1. 在 PrintServices.cs 增加 public string Xxx(string args)：用 ParseObject(args) 取参数，成功返回 Result.success(...)，失败返回 Result.error(...)。
  2. 把命令名加入 config/appsettings.json 的 allowedCommands（否则网络调用返回 403），并调用 CommandDispatcher.ResetCache() 或在设置页保存一次。
  3. 在 delta spec 里补 ## ADDED Requirements + ### Scenario:，在 tasks.md 勾选对应任务。
  4. WS 与 POST /api/command 自动可获得该能力；如需便捷端点，在 WebServerService.MapApi 增加 app.MapPost。
  5. 更新 ws.html / api.html 的命令表与示例。
单一分派入口： UI、WebSocket、REST 全部调用 CommandDispatcher.Execute，不要在页面里另写一套业务逻辑。这样命令行为一致、白名单统一、文档不漂移。
