模板 + 数据打印

面单 / 标签场景：JSON 请求信封（template + data + 打印参数）→ 客户端把 data 替换进 template 的 {{占位符}} → HTML 转 PDF → 打印。HTML 是版面（CSS 像素级锁定 100×150 / A4 等尺寸），JSON 是参数信封，二者解耦。

为什么用 HTML 而不是 XML：客户端内置 HTML 打印链路（无头浏览器 --print-to-pdf → SumatraPDF），版面在转 PDF 时即固化，跨驱动一致；XML/XSL-FO 无现成打印链路、调版面累。面单系统本身多为 Web 技术栈，模板即 HTML 组件，零转换。

请求信封（JSON）

命令 TemplatePrint，经 REST /api/command 或 WebSocket 下发。字段：

字段类型必填说明
templatestring是HTML 模板。三种形态：内联文本 / 本地文件路径 / URL（CDN/S3 直链）
dataobject否{{key}} → 值。值自动做 HTML 转义，防止订单数据里的 < & " 破坏版面或注入
printerstring否目标打印机；留空走默认 / 自动分流
paperKindstring否纸张：A4/100mm x 150mm 自定义毫米等，配合尺寸匹配引擎
copiesint否份数，默认 1
fitstring否fit/shrink/noscale，默认 fit
scalestring否portrait/landscape
printPagesstring否页码范围，默认 1-

三种 template 形态

内联 HTML

template 直接是 HTML 字符串。适合短模板、调试、测试页。

本地文件

template 是已存在文件路径（.html/.htm）。适合预置模板包。

URL（CDN/S3）

template 是 https://tpl.cdn.com/waybill/100x150.html。客户端自动下载再渲染。模板放 CDN 直链，JSON 只传业务参数——模板改版不动客户端。

示例：面单（100×150）

{
  "cmd": "TemplatePrint",
  "template": "https://tpl.example.com/waybill/100x150.html",
  "data": {
    "单号": "SF20261114001",
    "收件人": "张三",
    "收件电话": "13800000000",
    "收件地址": "上海 浦东新区 张江高科技园区 88 号",
    "寄件地址": "深圳 南山区 科技园 1 号",
    "qr": "SF20261114001"
  },
  "paperKind": "100mm x 150mm",
  "copies": 1,
  "fit": "fit"
}

对应 HTML 模板（100×150）

<div style="width:100mm;height:150mm;box-sizing:border-box;
            padding:4mm;font:12px/1.5 'Microsoft YaHei'>
  <h3 style="margin:0 0 2mm">{{单号}}</h3>
  <p>寄：{{寄件地址}}</p>
  <p>收：{{收件人}} <span style="font-weight:700">{{收件电话}}</span></p>
  <p>{{收件地址}}</p>
  <img src="{{qr}}" style="position:absolute;right:4mm;bottom:4mm;width:22mm;height:22mm"/>
</div>
占位符规则：只有 data 里存在的键会被替换；未出现的 {{key}} 保持原样。替换值已 HTML 转义（对象/数组先序列化为 JSON 文本再转义）。

二维码：本地生成，不依赖外网

data.qr 传二维码数据（如单号），客户端用内置 zxing 在本地出码，替换进 {{qr}} 的 data:image/png。面单系统无需上传图片、不依赖外网 CDN 可达——断网也能打。模板里写 <img src="{{qr}}"> 即可。

尺寸匹配与自动分流（面单 + A4 混带）

面单多类型（100×150 / 100×180 / 75×130 …）+ 偶发 A4。不想频繁手动换打印机时，靠 paperKind + 打印机实际纸张能力自动分流：

需求可用纸张匹配度处理
100×150 面单100×150100%直打，最稳
100×150 面单100×180高（容差 30mm）按 100×180 介质打，内容区 100×150，上下留白——可用，非 100% 匹配但成品不跑版
A4 单据A4100%直打
100×150 面单仅 A4低缩放/A4 留白 或 挂起待人工
非 100% 匹配策略：宽度优先精确匹配，高度差在容差内（默认 30mm）判为可用并按介质实际尺寸出图；超出容差则降级（缩放 or 挂起）。同批同尺寸面单路由到同一台，避免反复切换打印机。

稳定性：HTML → PDF 链路

模板渲染产物先进入 temp/，再由无头浏览器 --print-to-pdf 固化为 PDF，最后经 SumatraPDF 打印。版面在转 PDF 时即锁定，与打印驱动解耦。

  • 客户端收到 TemplatePrint，按 template 形态取模板（URL 则下载）
  • 用 data 做 {{占位符}} 替换（值已 HTML 转义），写入 temp/xxx.html
  • 无头浏览器 --print-to-pdf 生成 temp/xxx.pdf
  • SumatraPDF 按 paperKind/fit/copies 打印，结果入队（/api/queue 可查）

    • 与云端的配合（SaaS / 独立部署）

    云端（Golang 后端 + 内嵌 Next.js）负责：模板库管理（上传 HTML 模板 → S3 兼容存储 + CDN 域名）、订单→参数 JSON 组装、设备注册与鉴权。客户端只认「模板 URL + data JSON」，存储后端（OSS/COS/MinIO/R2）可互换，客户端零改动。

    面单系统/中台 ── 订单+参数 JSON ──► 云端 Go 服务 ── 选模板(CDN URL)
                                              │
   客户端 ◄── TemplatePrint(template=URL, data=…) ◄┘
   （自动下载模板 + 替换 + 转PDF + 打印 + 结果回传）
